# Auto-Update Troubleshooting Guide

## Recent Changes

The auto-updater error handling has been improved to provide more detailed error messages and better logging for debugging.

### What Was Fixed

1. **Enhanced Error Messages**: The generic "An error occurred while checking for updates" message now includes specific details about:
   - Network errors (connection issues)
   - 404/Not Found errors (update server unavailable)
   - Connection refused errors (firewall/network issues)
   - HTTP errors (server-side issues)

2. **Detailed Logging**: Added comprehensive console logging to help diagnose issues:
   - App version and configuration
   - Platform and architecture
   - GitHub token status
   - Update availability details
   - Download progress with byte counts
   - Error stack traces

3. **GitHub Token Support**: Added support for private repositories via `GH_TOKEN` environment variable

## Common Issues and Solutions

### Issue 1: "Update server not found" (404 Error)

**Cause**: No GitHub release exists for the current version or newer.

**Solution**:
1. Check if releases exist: https://github.com/uptick-dev/downtick/releases
2. Ensure the release has the proper assets (.dmg, .zip, latest-mac.yml)
3. Verify the release is published (not draft)

### Issue 2: "Cannot connect to update server"

**Cause**: Network connectivity or firewall blocking GitHub.

**Solution**:
1. Check internet connection
2. Verify GitHub is accessible: `curl -I https://api.github.com`
3. Check firewall settings
4. Try from a different network

### Issue 3: Private Repository Access

**Cause**: Repository is private and requires authentication.

**Solution**:
Set the `GH_TOKEN` environment variable before starting:

```bash
export GH_TOKEN=your_github_token_here
npm start
```

### Issue 4: Download Fails After Finding Update

**Cause**: Asset file missing or corrupted on GitHub release.

**IMPORTANT**: electron-updater requires **ZIP files**, not DMG files!

**Solution**:
1. Check the release assets include:
   - `Downtick-1.x.x-mac.zip` (REQUIRED for auto-updates)
   - `Downtick-1.x.x-x64.dmg` (optional, for manual installation)
   - `Downtick-1.x.x-arm64.dmg` (optional, for manual installation)
   - `latest-mac.yml` (auto-generated by electron-builder)
2. If only DMG files exist, the build configuration needs to be updated (see below)
3. Re-publish the release with ZIP files:
   ```bash
   npm run publish
   ```

**Why ZIP and not DMG?**
- DMG files are for manual download and installation by users
- ZIP files are required by electron-updater for automatic updates
- You should publish BOTH formats: DMG for users, ZIP for auto-updater

### Issue 5: "HttpError" Messages

**Cause**: GitHub API rate limiting or server issues.

**Solution**:
1. Wait a few minutes and try again
2. Check GitHub status: https://www.githubstatus.com
3. If using a GitHub token, verify it has the correct permissions

## Verifying a Successful Update

When updates work correctly, you should see:

1. **Check Phase**:
   ```
   Checking for updates...
   Update available: 1.2.0
   Update info: { version: "1.2.0", ... }
   ```

2. **Download Phase** (after clicking "Download Update"):
   ```
   Starting update download...
   Download speed: 1234567 - Downloaded 25% (1234567/4938268 bytes)
   Download speed: 1234567 - Downloaded 50% (2469134/4938268 bytes)
   ...
   Update downloaded
   ```

3. **Install Phase** (after clicking "Restart Now"):
   - App quits
   - Update installs
   - App restarts with new version

## Build Configuration for Auto-Updates

### Required: ZIP + DMG Targets

Your `package.json` must include BOTH `zip` and `dmg` targets:

```json
"mac": {
  "target": [
    {
      "target": "dmg",
      "arch": ["x64", "arm64"]
    },
    {
      "target": "zip",
      "arch": ["x64", "arm64"]
    }
  ]
}
```

This configuration has been updated in your `package.json`. When you run `npm run publish`, it will now generate:

- `Downtick-1.x.x-x64.dmg` - Manual installation for Intel Macs
- `Downtick-1.x.x-arm64.dmg` - Manual installation for Apple Silicon Macs
- `Downtick-1.x.x-mac.zip` - Auto-update package (universal or architecture-specific)
- `latest-mac.yml` - Update metadata file

### Next Steps After Configuration Update

1. **Bump the version** in `package.json`:
   ```json
   "version": "1.1.1"
   ```

2. **Commit and push**:
   ```bash
   git add package.json
   git commit -m "Add ZIP target for auto-updates"
   git push
   ```

3. **Publish new release**:
   ```bash
   npm run publish
   ```

4. **Verify the release** includes ZIP files on GitHub

5. **Test auto-update** from an older version

## Technical Details

### Auto-Updater Configuration

From `package.json`:

```json
"publish": [
  {
    "provider": "github",
    "owner": "uptick-dev",
    "repo": "downtick"
  }
]
```

This tells electron-updater to check `https://github.com/uptick-dev/downtick/releases` for updates.

### Update Flow

1. App checks GitHub releases API for versions newer than current
2. If found, shows "Update Available" dialog
3. User clicks "Download Update"
4. Downloads the release asset (`.dmg` or `.zip`)
5. Verifies signature and integrity
6. Shows "Update Ready" dialog
7. User clicks "Restart Now"
8. App quits, installer runs, app restarts

### Files Involved

- `main.js`: Auto-updater configuration and event handlers
- `package.json`: Repository and build configuration
- GitHub Releases: Hosts the update files
